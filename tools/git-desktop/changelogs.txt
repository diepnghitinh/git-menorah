GitMenorah: changelog
=====================

Newest release first.


1.0.8 (2026-10-24)
------------------

New
- Note colors. The dot in a note's title bar opens seven paper colors:
  yellow, orange, pink, purple, blue, green and gray. Each note keeps its own
  color, saved with the canvas, and the minimap shows notes in their colors.
  Existing notes stay yellow.
- Safety checks in AI Hub. Before running a command on its own, Claude Code
  sends a separate turn asking whether the command is safe (the auto mode
  permission classifier, Bash command checks). These turns pass through on
  Claude as before; "Let the router judge safety checks" has the judge sort
  them into a task too, so they run on that task's model. Turns carrying
  Anthropic safeguards always stay on Claude.
- Vietnamese typing in terminals (Settings › Vietnamese typing), Telex or
  VNI, in canvas terminals, agent prompts and the Terminal tray of the Git
  tab. Press Control + Shift or click VI / EN on a terminal's title bar to
  switch. A word that is not Vietnamese spelling (push, sort, class…) stays as
  typed. When this computer already runs a Vietnamese keyboard (UniKey,
  OpenKey, EVKey, GoTiengViet, XKey…) the built-in typing turns itself off.
  On by default when the system language is Vietnamese.

Changed
- Notes on the canvas no longer follow Dark / Light mode. A note keeps the
  same paper and ink color in both modes, so it reads the same however the
  app is set.
- In Dark mode, terminals on the canvas have a soft light glow around them,
  so they stand out from the dark canvas.
- The project menu at the top of the canvas lists the repositories from the
  Project tab under "From the Project tab": click one to open it as a new
  board without picking its folder by hand. Repositories that already have a
  board are left out; type to filter when there are more than 8.


1.0.7 (2026-10-23)
------------------

New
- AI Hub with an Inference Router (AI Hub in the left rail). It works with
  Claude Code only; Codex and shells are never routed. Turn the router
  on and give a project a router: Software Engineering (bug fixing, new code,
  tests, performance, architecture, UI, review and security, DevOps, docs) or
  AI Engineer (training and fine-tuning, data pipelines, AI-generated data,
  LLM apps and agents, prompts, evals, data analysis, AI system design,
  MLOps). Claude Code sessions opened from that project's canvas then talk to
  a local proxy on 127.0.0.1, which forwards each request to your real
  endpoint: ANTHROPIC_BASE_URL from ~/.claude/settings.json, the environment,
  or api.anthropic.com (Upstream URL overrides it). Each sub-agent task other
  than Explore is judged once by a small model, Claude Haiku 4.5 by default
  or a provider from Settings ("Try the judge" tests it), and sorted into one
  of the router's tasks. Every task can run on its own Claude model, e.g.
  Opus for architecture and UI, Haiku for tests and docs; when Anthropic
  refuses that model, the original request is sent again. The main loop,
  side requests, Explore and safety checks pass through unchanged. Projects
  without a router, and agents other than Claude Code, run directly as
  before. A router assigned to a project applies to Claude sessions opened
  after that; turning the router off takes effect from the next turn.
- "Set target" on a task saves a provider and model for it ("saved · runs on
  Claude"). The turns still run on Claude until protocol translation for
  other providers is in.
- Statistics, a tab inside AI Hub (Router | Statistics): a Flow diagram of
  Claude Code → router → task → answering model, sized by turns, tokens or
  estimated cost, for Today, 7 days, 30 days or All, and for all projects,
  one project or "Outside Git Menorah". Every turn, judge turns included, is
  stored in a local database in the app's data folder: router, task, model,
  tokens, cost and time, no prompt text. "Delete data" clears it.
- Claude Code outside the app can use the router too: AI Hub → "Claude Code
  outside Git Menorah" → "Install into settings.json" points
  ANTHROPIC_BASE_URL in ~/.claude/settings.json at the proxy, so Claude Code
  in your own terminal or IDE goes through the router you choose there ("No
  router" passes it through without logging). The original file is backed
  up next to it; "Restore original" puts it back, or only the old
  ANTHROPIC_BASE_URL when the file was edited after the install. While
  installed, Claude Code needs GitMenorah to be running; the proxy keeps the
  same address across restarts.
- Settings in the left rail lists AI providers: OpenRouter, OpenAI, Google
  Gemini, DeepSeek, Ollama, any OpenAI-compatible server (vLLM, LM Studio,
  LiteLLM…) and TypeSafe (Jev, for the router judge only). Add provider tests
  the connection before saving; each card shows its status, model count, last
  check and what uses it. API keys are encrypted with the OS keychain and
  never shown again, only their last characters; without a keychain the key
  is not saved.
- AI Hub and Settings are in English.
- Update notices from GitHub Releases. 15 seconds after start and then every
  6 hours the app checks github.com/diepnghitinh/git-menorah/releases; when a
  newer version is out it shows its release notes with Download (the .dmg or
  .zip for this Mac or PC, opened in the browser), Open Release Page, Later
  and Skip This Version. GitMenorah → Check for Updates… (Help menu on Windows) checks right
  away; turn the automatic check off in Help → Check for Updates
  Automatically. Help → Release Notes opens the releases page. The app does
  not install updates itself: builds are not signed, so download and replace
  the app as before.
- Drag a branch onto another branch in the Git tab to merge or rebase, e.g.
  drag feat/… onto staging and choose "Merge feat/… into staging" or "Rebase
  feat/… onto staging". Works with the branches in the sidebar and the branch
  labels on the commit graph; a valid drop target is outlined. The command
  runs in the worktree that has the branch checked out (merge: the target;
  rebase: the dragged branch). If no worktree has it, the current worktree
  switches to it first, and the confirmation says so. Merge conflicts in
  another worktree open that worktree. Remote branches can be merged, not
  rebased. The usual rules still apply: no merges into main / staging / prod
  in gitflow repositories, no rebasing shared or already pushed branches.
- Push any local branch from its right-click menu without switching to it:
  "Push to origin/feat-x" when it has an upstream, otherwise "Push to origin"
  (one item per remote), which also sets the upstream. A branch whose remote
  copy was deleted gets a warning that the push creates it again.
- Delete branches from the Git tab sidebar: right-click a local branch →
  "Delete feat-x…", or a remote branch (or a local branch with an upstream)
  → "Delete origin/feat-x from the remote…". The current branch, branches
  checked out in a worktree and shared branches (develop, main, staging,
  prod) cannot be deleted. When the branch has commits found on no other
  branch, the confirmation lists how many with the SHA to get them back, and
  needs a tick before Delete. Deleting the local branch keeps its remote
  copy and the other way round.
- Links between canvas nodes show arrows pointing at the node whose context
  can be read: terminals read linked nodes with menorah-context, notes and
  images cannot. Hover a link to see who reads whom.
- Dark mode for the whole app. The color theme picked in the Git tab
  (System, Light or Dark) now also applies to the Canvas, Projects, AI Hub
  and Settings, and is remembered for the next start.

Changes
- "New branch…" and "New worktree…" stay at the bottom of the Branch menu
  at the top of the Git tab; a long list of worktrees and branches scrolls
  above them instead of pushing them out of sight.
- The collapsed notch is narrower: 282 points instead of 328. It now fits the
  real notch (185 points on a 14" / 16" MacBook) and the wings only take the
  room the agent logo and the count need.

Fixes
- Double-click a branch in the Git tab sidebar, or a branch label on the
  commit graph, to switch to it (a branch open in another worktree opens that
  worktree). It used to do nothing: the first click selects the branch's tip
  commit and redraws the list, so the browser never saw a double-click.
- Pasting an image into a terminal or the Chat panel works again. With
  Electron 44 the clipboard image reader was removed and ⌘V of a screenshot
  failed silently; pasting an image onto the canvas was affected too.
- Telegram "Copy Media" (and any copied image or file, e.g. from Finder) can
  be pasted into a terminal: the file's path is typed in, so Claude Code reads
  the image. Files from another app's temporary folder are copied to the
  uploads folder first, because that app deletes them soon and macOS may keep
  the agent from reading them. Plain text pastes as before.
- The prompt cache chip on Claude nodes ("cold" or the countdown) no longer
  blinks on and off. Clicking between nodes, typing or resizing makes Claude
  Code redraw its screen, and that redraw counted as "running" for 1.5
  seconds, which hid the chip. Output right after a key, focus change or
  resize is now treated as a redraw. The status dot, the notch and the cache
  notice no longer flash "running" for it either.
- Commit details in the Git tab label the parent commits "parent" /
  "parents" instead of the Vietnamese "cha".


1.0.6 (2026-10-22)
------------------

New
- Name and email for commits in the Git tab. The Commit box shows
  "Committing as name <email>", marked as this repository or global, with a
  Set… / Change… button. The dialog saves to the repository's .git/config or to
  ~/.gitconfig; saving globally also removes the repository's own value so the
  new one takes effect. Committing no longer fails with a "run git config
  user.email" hint that sent you to a terminal.
- Live push progress in the Git tab toolbar, e.g. "Writing objects 45%" with a
  small bar, instead of a bare "Running…" until the push finished. Command
  history still shows only the approved command.
- Prompt cache clock on Claude nodes. While Claude is waiting, the node header
  shows how long its prompt cache stays warm (usually 1 hour from the last
  request); it turns amber in the last minutes and red ("cold") once expired,
  when the next prompt re-sends the whole context. Click it to run /compact.
  The notch shows the same "cache 12:34" / "cache cold".
- A notification a few minutes before a Claude session's prompt cache cools;
  click it to open the session, then prompt or run /compact. On by default,
  turn it off in View → Notify Before Prompt Cache Cools.
- Markdown preview plays a standalone GitHub video link inline, as GitHub
  does, so the README demo video plays in the Files view.

Fixes
- Browse… in "Add project folder" and "Add repository outside the project"
  works on Windows. It used to say the folder picker is macOS only; it now
  opens the Windows folder dialog, and folder names with accents or CJK
  characters come back intact.
- Copying text from a terminal on the canvas no longer garbles non-ASCII
  characters ("có làm gì" became "c√≥ l√†m g√¨"). When the app is started from
  Finder or the Dock it has no LANG, so the clipboard read UTF-8 as Mac Roman;
  terminals now get LANG=en_US.UTF-8 unless a locale is already set.
  Vietnamese, Chinese, Japanese, Korean, emoji and every other script copy
  correctly. Applies to terminals opened after the update.
- Copy in the Git tab works again. Copy SHA, Copy summary, Copy branch name,
  Copy path and the other copy actions showed "Clipboard blocked by the
  browser" in the app, because the Git tab runs in a frame that was not
  allowed to write to the clipboard. The frame now has that permission, and
  when the browser still refuses (an older browser, or the page opened over
  plain http from another machine), the copy falls back to the classic way.


1.0.5 (2026-10-22)
------------------

New
- Discard in the Unstaged list. Each file and folder row has a Discard button
  next to Stage, the Unstaged heading has "Discard all", and the diff of an
  unstaged file has Discard too. Changed and deleted files go back to their
  staged (or committed) version with git restore --worktree, so a file's staged
  part is kept; untracked files are deleted with git clean -f. It always opens
  the confirmation with the exact commands, because discarded changes cannot be
  recovered. Untracked secret files (.env.local, keys…) are never deleted from
  the page, and conflicted files are left alone.
- Markdown preview in the Files view. A .md file opens with a "Preview | Code"
  switch: Preview renders headings, lists and task lists, tables, quotes, code
  blocks with colours, links and images from the repository; Code shows the
  source with line numbers. Links to other files in the repository open them
  in a tab, #section links scroll to the heading. Raw HTML in the file is shown
  as text, not run. The choice is remembered.
- Accounts (Settings → Accounts, or GitMenorah → Accounts…): sign in to
  GitHub, GitHub Enterprise, GitLab (also self-hosted), Bitbucket Cloud or any
  other host with a personal access token, like in Sourcetree. The token is
  checked with the provider and stored by git's credential helper (macOS
  Keychain or Git Credential Manager), so fetch, pull, push and clone use it in
  the app and in every terminal. GitMenorah keeps no copy; git.json only lists
  the accounts. If git has no credential helper, Settings offers to turn one on.
- Clone from URL (File → Clone Repository…, ⇧⌘C / Ctrl+Alt+C; the + of the
  canvas tab bar; the repository menu and Projects page of the Git tab). Paste
  an HTTPS or SSH URL, or pick a repository from a signed-in account. The dialog
  shows the exact git clone command; the clone runs in the background and the
  repository is added to the Git tab (to its project group when it lands in a
  project folder). The last "Clone into" folder is remembered.
- The first-run prompt offers "Clone from URL…".
- Paste an image onto the canvas (⌘V / Ctrl+V while no terminal or text box
  has focus): a screenshot, an image copied from a browser, or an image file
  copied in Finder becomes an image node under the mouse. Image nodes work like
  in Figma: no frame, the name and buttons sit above the image and show on
  hover; drag the image to move it; drag a corner or edge to resize it with
  its aspect ratio kept (hold ⇧ to resize freely, double-click to get the
  ratio back); Delete / Backspace removes the selected image. Drop an image
  node onto a terminal or note to hand its path over; it springs back to its
  place. New image nodes take the image's own proportions, and are sharper
  when zoomed in.

Changes
- Pull on a branch that has diverged from its upstream: the fast-forward
  confirmation now offers the pull that works, in one click. "Pull with
  rebase" when your local commits are not on the remote yet (no merge commit),
  otherwise "Pull with merge". Shared and protected branches still never get a
  rebase, and gitflow branches stay fast-forward only. This switches just that
  pull, not the pull mode chosen in the toolbar.
- Pull with merge or rebase no longer asks you to commit or stash first.
  Uncommitted changes are stashed and put back after the pull (--autostash);
  the confirmation says so. Merge pulls need git 2.27 or later for this; with
  an older git the old rule (commit or stash first) stays.
- The canvas tab bar is a breadcrumb: [project ▾] / tab 1 · tab 2 … The
  project button opens the project list (switch, remove, Open Folder…), which
  used to sit behind the project square at the top of the rail; that square is
  gone. With no project open the bar shows just "Select Folder Project". A new
  project's first tab is named after the project folder. The + menu is now
  just "Open Folder…", "Clone from URL…" and the repositories you already have
  (with a filter when there are many).
- Settings has tabs: Accounts and Terminal limits.
- An empty canvas no longer shows the "Choose a project folder" card. Open a
  folder or repository with "Select Folder Project" in the canvas bar.
- README rewritten: GitMenorah as a Git worktrees UI and one place to manage
  every agent, with a download link to the GitHub Releases page.

Fixes
- Worktrees heading in a narrow sidebar: the "Newest | A–Z" switch wrapped and
  pushed the count out of view. It is now one sort icon next to +; a click
  opens a menu with "Newest first" and "Name (A–Z)". Long section titles end
  in "…" instead of crowding the buttons.


1.0.4 (2026-10-21)
------------------

New
- New worktree from the main worktree. Press + next to "Worktrees" in the
  sidebar, use the main worktree menu, or right-click any worktree and choose
  "New worktree from <branch>…". The branch defaults to the one the main
  worktree is on, and the worktree is created in .worktrees/<name>.
- The canvas, Chat panel, notch, Settings dialog, menorah-context command and
  agentd messages are now fully in English.
- README.md with screenshots, and the MIT License (LICENSE).
- The Git page runs on its own: node tools/git-server.mjs serves git.html,
  with no dev-runner around it. The desktop app uses the same server.
- "Add Project Folder…" (Shift+Cmd+O) adds a folder of repositories as a
  project group. It replaces "Open Project Folder…".

Changes
- Publisher is now InChurch.app (app copyright and Windows company name).
- Repositories and project groups are saved in ~/.config/gitmenorah/git.json
  (GITMENORAH_CONF to change). Repositories added in earlier versions have to
  be added again.
- Gitflow protection applies only to repositories that have a develop branch.
- Repository labels show the full folder name.
- Linking node_modules into new worktrees is off by default; turn it on with
  "linkNodeModules": true in git.json.
- Theme, layout and the last opened repository are reset once.
- Messages say "pull request" instead of "merge request".
- The "New branch" dialog keeps its own "Open in its own worktree" choice;
  creating a worktree from the + button no longer changes it.


1.0.3 (2026-10-21)
------------------

All heavy work of the agent canvas moved to a child process, menorah-agentd,
written in Go. Electron only relays data. Screens and interactions are
unchanged.

New
- menorah-agentd runs terminals (PTY), CPU / RAM limits, the Chat panel,
  sub agents, the notch, Codex session discovery and the menorah-context
  command.
- If agentd crashes, open terminals report "exited" instead of hanging in
  "Running". agentd restarts after 1 second and reloads the CPU / RAM limits
  and canvas wiring. Claude / Codex sessions reopen from the canvas, just like
  after quitting the app.
- If Electron dies unexpectedly, agentd stops every session and exits, so no
  agent is left orphaned.
- agentd idles at about 6 MB of RAM. Reading transcripts takes about 12 MB,
  down from up to 423 MB.

Fixes
- The Chat panel shows the tool summary line again (e.g. "Bash · npm test").
  The old code had two functions with the same name, so the line was always
  empty.
- Pressing Cancel in the "terminals still running" dialog on quit keeps the
  sessions alive. The old version stopped them anyway.

Technical changes
- Removed node-pty and workspace/limits.cjs. Windows uses ConPTY.
- The terminal replay buffer is still capped at 512 KB, now counted in bytes.
  When full it is trimmed to 384 KB in one step.
- Without the agentd binary the app still opens and the Git tab works; only
  terminals report "Could not start menorah-agentd".

Notes
- Building needs Go 1.22 or later. No cgo, so the Windows build can be made on
  a Mac.
- Run from source: cd tools/git-desktop && npm ci && npm start. npm start
  builds bin/menorah-agentd first. bin/ is not tracked by git.
- npm run agentd only works on macOS / Linux. On Windows, build with
  tools/build-git.sh --platform=windows.
- Windows: CPU / RAM limits are measured, not enforced.


1.0.2 (2026-10-21)
------------------

New
- GitMenorah → Settings… (⌘,): set max CPU (cores) and max RAM (GB) for the
  whole process tree under every terminal. Values are stored in settings.json.
  - Over CPU: child processes are throttled by pausing and resuming them in
    100 ms cycles.
  - Over RAM: the child process using the most RAM is stopped and a toast
    tells you.
  - The session shell and the agent itself are never throttled or stopped.
  - Windows only measures, it does not enforce.


1.0.1 (2026-10-21)
------------------

New
- Terminal button in the Git tab, between Refresh and the theme button. It
  opens a shell in the bottom tray at the repository / worktree being viewed,
  without adding a canvas node. Each tab is one shell: + opens another, x stops
  it, typing exit closes the tab. Shortcut ⌃`.
- The bottom tray has two tabs: Command history | Terminal. The Terminal tab
  only shows while a shell is alive. Click the open tab again to close the
  tray; shells keep running.
- Drag the top edge of the tray to resize it; each tab remembers its own
  height. Double-click the handle to reset to 260 px.
- Shells follow the page theme and switch colors when the theme changes.

Fixes
- Packaged builds reported "This build has no xterm": the app blocked the
  /vendor/ folder by mistake.
- The Sub agent strip and menu showed the word "null".
- Command history was squashed, entries overlapped and output was cut off.
- Reloading the page only reconnects shells that are still alive; it no longer
  opens new shells after the app restarts.
